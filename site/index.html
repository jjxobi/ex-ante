Forecasts, filed before the fact.

Probabilistic earthquake rate forecasts for New Zealand, committed to a public git history before the window they describe, then scored in the open against what happened.

ex ante / before the event. The opposite of how a backtest reasons.

Every forecast, and the gap it was filed into

Each track runs from the moment a forecast was committed to the window it describes. The gap is the argument: it cannot be manufactured afterwards, and the code raises an error rather than writing a forecast once its window has opened.

Why the gap is the point

Every forecasting portfolio shows a backtest. Backtests are cheap and unfalsifiable: fit a model to history, tune until the number looks good, publish the number. Nobody can tell what was tried and discarded.

This cannot do that. A forecast is written to git with a content hash and a timestamp GitHub records on its own servers, hours before the window opens. Publishing into a window that has already started raises an error instead of writing a file, so a missed window stays missed and shows below as a permanent gap in the record.

Do not trust this page

It is generated by the project it describes. Check it yourself instead.

git clone https://github.com/jjxobi/ex-ante
cd ex-ante
python scripts/audit_history.py --online

The audit reads git history rather than the current checkout, so a forecast altered and altered back cannot look honest. It imports nothing from the forecasting code, because an auditor built on what it audits inherits its bugs. It refuses to run against a shallow clone rather than report a clean result it did not earn. Every check is mutation tested: disabling any one of them breaks at least one test.

With --online each forecast is checked against the GitHub Actions run that produced it. That start time is recorded server side, and is the one timestamp neither the author nor this repository can set.

What is actually being forecast

Rates, not alarms. No prediction of individual earthquakes.

Expected count of magnitude 3.0 and above events per cell per window, across a frozen grid of 4,100 cells at 0.1 degree resolution, split into two depth strata at 41 km and scored separately. The grid, the magnitude threshold and the depth boundary were fixed before publication began and are locked by hash, so they cannot be quietly retuned to flatter a result. Scoring uses the standard CSEP consistency tests.

The baseline is wrong by 32.7 percent, on purpose

It over predicts the event rate against its own fitting window. That was measured before going live and recorded rather than repaired, because a forecast claiming no known weaknesses is the least believable kind. It is also the number the next model has to beat, and leaving it in place is what makes that comparison mean anything.
