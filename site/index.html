Ex Ante

Probabilistic earthquake rate forecasts for New Zealand, committed to a public git history before the window they describe, then scored in the open against what actually happened.

ex ante · before the event. The opposite of how a backtest reasons.

Why this exists

Every forecasting portfolio shows a backtest. Backtests are cheap and unfalsifiable: you fit a model to history, tune until the number looks good, and publish the number. Nobody can tell what you tried and discarded.

This project cannot do that. A forecast is written to git, with a hash and a server side timestamp from GitHub, hours before the window it describes opens. The code physically refuses to publish a forecast for a window that has already started, so a missed window stays missed and shows up below as a permanent gap. There is no version of this record in which a bad forecast can be quietly improved after the fact.

Verify it yourself

This is the part that matters. Do not take the table above on trust: it is generated by the same project it describes.

git clone https://github.com/jjxobi/ex-ante
cd ex-ante
python scripts/audit_history.py --online

The audit reads git history rather than the current checkout, so a forecast that was altered and altered back cannot look honest. It imports nothing from the forecasting code, because an auditor built on the thing it audits inherits its bugs. It refuses to run against a shallow clone rather than reporting a clean result it did not earn. Every check is mutation tested: disabling any one of them breaks at least one test.

With --online it also checks each forecast against the GitHub Actions run that produced it. That start time is recorded server side and is the one timestamp neither the author nor this repository can set.

What it forecasts

Rates, not alarms. No prediction of individual earthquakes.

Expected count of magnitude 3.0 and above events per cell per window, over a frozen grid of 4,100 cells at 0.1° resolution, split into two depth strata at 41 km and scored separately. The grid, the magnitude threshold and the depth boundary were fixed before publication began and are hash locked, so they cannot be quietly retuned to flatter a result. Scoring uses the standard CSEP consistency tests.

A known deficiency, published deliberately

The baseline model over predicts the event rate by 32.7% against its own fitting window. This was measured before going live and recorded rather than repaired, because a forecast claiming no known weaknesses is the least believable kind. It is also the target the next model has to beat.
